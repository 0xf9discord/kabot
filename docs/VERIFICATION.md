# 검증 결과

## 0.3.0 및 2026-11-08 확인

- Android26.8.2 비밀번호 인증·휴대폰 등록 API와 암호화 세션 저장을 추가했습니다.
  비밀번호는 저장하지 않고, 사용자 직접 입력은 로컬 창/터미널에서만 처리합니다.
- 최초 실제 계정 인증과 세션 저장은 2026-10-31 성공했으나, 이후 채팅 서버 인증서의
  이름 검증에서 실패했습니다. 이 상태를 채팅 접속 성공으로 간주하지 않았습니다.
- IP 배정과 TLS 인증서 이름을 분리했습니다. Android의 배정된 채팅 IP에 연결할 때
  `kakao.com`으로 검증하며 CA 서명과 호스트 검증을 유지합니다. 올바른 DNS 서비스
  이름으로 IP에 연결하는 로컬 TLS 테스트와 잘못된 이름을 거부하는 테스트가 통과했습니다.
- 2026-11-08 기존 세션은 TLS 연결 후 `LOGINLIST -950`(만료/무효 토큰)으로 거부됐습니다.
- 사용자 직접 재로그인 후 **계정 인증과 실제 LOGINLIST 성공**, 채팅방 항목28개 수신을
  확인했습니다. 진행 파일에는 성공 여부·단계·개수만 남기고 계정 ID/토큰/내용은 남기지 않습니다.
- 한 번의 답장 테스트는 로컬에서 방을 선택하고 `START`를 입력한 뒤에만 시작합니다.
  가짜 클라이언트 자동 테스트10개로 전송 전 명시적 승인, 대상·발화·작성자·기존 로그
  필터, 최대1회 전송, 시간 초과·불확실 전송의 무재시도를 검증했습니다.
- 독립 봇 호스트 실행에는 카카오톡 앱이나 GUI가 필요하지 않습니다. GUI는 사용자가
  로컬에서 계정/세션 암호를 입력하고 테스트 대상을 고르는 선택적 편의 도구입니다.

실제 오픈채팅 답장 확인: **2026-11-08**, 사용자가 로컬 창에서 테스트할 방과 답장을
확인하고 START를 입력한 뒤 다른 계정의 새 `/핑`을 수신했습니다. 답장1회/시도1회의
서버 성공 응답을 기록했고, 사용자가 실제 방에서 답장이 보인다고 확인했습니다.
테스트는 한 번 답한 후 연결을 닫았습니다. 검증 상태에는 이름/ID/내용 대신 단계와
개수만 기록했습니다. 처음에는 오픈채팅 필터로 대상 방이 숨겨졌으며, 전체 LCHATLIST와
읽기 전용 CHATINFO/INFOLINK로 서버 이름을 확인하고 명시적 allow_open 설정으로 수정했습니다.

네이티브 카카오톡 앱을 실행하거나 UI를 제어하는 코드가 봇의 런타임 의존성이 아닙니다.
현재 텍스트 수신·응답 경로를 확인했으며, 토큰 자동 갱신/이미지 송신/새 방 참여·관리/
E2E 비밀채팅까지 검증한 결과가 아닙니다. 토큰 만료 시 같은 기기 ID로 재로그인합니다.

최종 패키지 확인: `0.3.0` wheel/sdist 생성에 성공했습니다. 프로젝트 환경에서139개
테스트가 통과했고, 별도 `.wheel-test` 환경에 wheel을 설치해 `site-packages`의 설치본으로
같은139개 테스트가 통과했습니다. `kabot init --personal`로 새 봇을 생성하고 로컬
시뮬레이터의 `/핑`, `/방문`, `/도움말`도 확인했습니다. 배포 파일에 사용자 세션·계정
기록·원본 실행 파일·메모리 덤프·IDA DB·참고 저장소 복사본이 들어가지 않음을 확인했습니다.
서드파티 MIT 고지는 wheel에 포함되어 있습니다. Ruff와 의존성 충돌 검사도 통과했습니다.

## 0.2.0 추가 검증

확인일: 2026-10-31, Asia/Seoul.

- 패키지 자동 테스트: **56 passed** (기존 20개 + LOCO 36개).
- 오프라인 압축 해제 도구: `python tools/test_static_unpack.py`, **7 tests OK**.
- 실제 loopback TCP 서버가 임시 RSA 키를 생성하고 핸드셰이크를 복호화한 뒤
  AES-GCM으로 Booking/CHECKIN/LOGINLIST, 분할된 MSG, CHATONROOM/WRITE를 검증.
- 중간에 끼어든 push 이벤트 보존, 큰 64비트 ID, 자기 메시지·다른 방·비텍스트·중복
  무시, 로그인 거부 무재시도, 요청 취소·시간 초과 연결 종료를 검증.
- 별도 `.wheel-test` 환경에 **0.2.0 wheel**을 설치하고 개발 소스 대신
  `site-packages`에서 불러옴을 확인.
- 추가 의존성 없이 기본 모듈 import 성공 확인 후 LOCO extra 의존성을 설치.
  wheel 설치본으로 LOCO 테스트 **36 passed**.
- wheel 안의 서드파티 MIT 고지 포함 확인. wheel/sdist에 네이티브 실행 파일,
  메모리 덤프·IDA DB·참고 소스 clone이 포함되지 않음을 확인.
- `ruff check src tests examples`, `ruff format --check src tests examples`,
  `pip check`: 모두 통과.

실제 카카오 서버에 LOCO 로그인하거나 사용자 메시지를 보내지 않았습니다.
이메일/비밀번호 인증·기기 등록·토큰 발급 및 최신 실서버 호환성은 여전히 미확인/미구현입니다.
네이티브 오프라인 복원은 IDA에서 관찰한 압축 계층의 복원이며, 공개 소스에서 가져온
LOCO 규격과 별도 근거입니다. 복원된20,889,600바이트, 재분석 함수1,860개의 근거는
`IDA_ANALYSIS.md`에서 확인할 수 있습니다.

추가 실행 관찰: 원본 x64 앱을 숨김 실행한 PID14432는 약10초 이내 자체 종료했습니다.
REA Frida attach 한 번은 해당 PID를 찾지 못해 실패했으며 세션/스크립트나 런타임 읽기는
생성되지 않았습니다. 남은 카카오톡 프로세스가 없음을 확인했습니다. 앱 자체 초기화의
파일/네트워크 동작은 관찰하지 않았고, 에이전트가 비밀번호를 입력하거나 사용자
데이터베이스/자격 증명을 읽거나 메시지를 발송하지 않았습니다. 실제 오류와 수명 기록은
`analysis/phase3-runtime/`에 있습니다. 이 실패를 런타임 코드 복구 성공으로 간주하지 않습니다.

## 0.1.0 최초 검증

확인일: 2026-10-31, Asia/Seoul.

- 프로젝트 `.venv`에 `pip install -e '.[dev]'` 설치 성공 (Python 3.11.9).
- `python -m pytest -q`: **20 passed**.
- `ruff check src tests`, `ruff format --check src tests`: 통과.
- `pip check`: 의존성 충돌 없음.
- `python -m build`: wheel과 sdist 생성 성공.
- 별도 `.wheel-test` 환경(Python 3.11.15)에 생성된 wheel만 설치 성공.
- wheel 설치본에서 CLI로 봇을 생성하고 실제 Uvicorn 서버를 임시 로컬 포트에 실행.
- 실제 HTTP로 `/healthz`, `/안녕 테스터`, `/방문` 2회 검증 성공; SQLite 값이 1, 2로 증가.
- 테스트 종료 후 서버 프로세스 종료 확인. 서버 로그에 비밀 경로 값이 출력되지 않음.
- wheel 안에 카카오톡 실행 파일이나 IDA 데이터베이스가 포함되지 않음을 확인.

자동 테스트는 명령어 경계/인자/정규식/액션/전처리, 응답 제한, 상태 TTL·동시 원자적 증가,
HTTP 비밀 경로·봇ID·본문 크기 검사, 시간 초과·예외 응답, 콜백 호스트 거부·전송,
OAuth state·토큰 갱신, REST 폼 인코딩·재시도·부분 발송 결과 보존을 검증한다.

카카오 실계정의 로그인·메시지 발송, 공개 HTTPS 도메인 연결 및 카카오 채널 배포는
수행하지 않았다. 실제 카카오 서버와의 성공을 검증한 결과가 아니다.
개인 계정/단체방 독립 클라이언트는 미구현이며 IDA 관찰 범위는 `IDA_ANALYSIS.md`에 있다.
